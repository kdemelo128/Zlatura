# GitHub prior-art scan for Zlatura (2026-10-22)

Scope: the owner's "scan GitHub for useful tools", run as a capped prior-art check (about 33 searches and fetches) across 8 areas. Public pages only: no GitHub API, no clones, no installs, nothing run. Every page was treated as untrusted data.
Skipped: the 30 repos already in `docs/proposals/dev-tools-and-reuse.md` section 3 (ponytail, mattpocock/skills, claude-plugins-official and the rest).

**Could not reach:** www.sec.gov, huggingface.co and www.promptfoo.dev (DNS failure), and npmjs.com (HTTP 403).

## What we already have (checked first)

- **Vendored:** pdf.js 4.7.76, ExcelJS 4.4.0, fflate 0.8.3 and tesseract.js 7.0.0.
- **Test-only:** axe-core, playwright and typescript.
- **CI:** actions are pinned by SHA, and Dependabot covers actions.
- **Mutation checks** are done by hand, per fix (`quality-gates` skill).
- **Storage and offline:** `app/store.js` (743 lines) and `sw.js` (196 lines), both hand-written and tested.
- **CSV:** `app/sheetread.js:20` `csvRows` and `app/textfile.js` `decodeText`, which handles encodings. There is a second CSV parser at `app/rentrollui.js:868` `parseCsv`: a duplicate worth folding into `csvRows` (noticed, not changed).
- **PDF tables:** rent roll and OM tables are rebuilt from pdf.js text positions (`app/pdftext.js`, `app/rentroll.js`, `app/omroll.js`).
- **Server:** `server/ai.mjs`, a stateless Node server.

## Ranked top 5 to integrate first

1. **actionlint and zizmor in CI** (rows 8–9).
   - **Approval gate:** new third-party CI tools. Pin each by release checksum and list them in `THIRD_PARTY.md` under test-only.
   - **Lands in:** a CI-only PR, the "F5b workflow lint" follow-up to F5 (#35); `check:quick` only.
   - **Why first:** cheap, offline, catches the workflow-injection class before F12 adds server secrets.
2. **gitleaks in CI**, run as the binary, not the action (row 10).
   - **Approval gate:** the same new-CI-tool gate, plus the owner choosing which history depth to scan the first time. Findings in old commits are reported structure-only.
   - **Lands in:** the same CI PR, or one just after it, and in any case before F12 (F12 introduces device tokens and server keys).
3. **osv-scanner on both lockfiles** (row 11).
   - **Approval gate:** CI tool, plus whether CI may call osv.dev (only package names leave; it is not user data) or uses `--offline` with a downloaded database.
   - **Lands in:** the CI PR. Vendored files stay covered by `THIRD_PARTY.md` checksums and Dependabot.
4. **fast-check property tests** (row 6).
   - **Approval gate:** a new devDependency, plus the Node 20 vs 22 decision (v5 needs 22.12).
   - **Lands in:** its own small test-only PR ("property tests: money rounding and text readers"). Its tests must fail on a mutated rounding rule. Golden stays identical (no app change).
5. **F12 adversarial set, built in-house** from the BIPIA and garak categories (rows 2–3). It covers document-borne injection, encoded payloads, "ignore previous" in tables and footnotes, and requests to reveal or exfiltrate data.
   - **Approval gate:** none for ideas. Copying any BIPIA strings is a copied-data gate (avoid; invent instead). An owner-run promptfoo or garak trial is a separate gate (telemetry and remote generation must be off).
   - **Lands in:** the F12 PR (`server/test/` fixtures).

**Not in the top 5:** the B2 SEC connector (build our own; it is gated on legal review), the C2a vCard and CSV exchange (build our own, reusing `csvRows`), and the storage, PWA, PDF-table and OCR libraries (ours already fit better).
