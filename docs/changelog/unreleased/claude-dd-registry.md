# A Documents card on every deal: which due-diligence documents you have, and which are missing

Step D3a of `docs/proposals/underwriting-evolve.md` (section 8; the data format approved 2026-10-29: `deal.dd`, a silent migration step, no document bytes stored). It records documents and shows a checklist; it adds no reader, stores no money and changes no figure.

- **Documents card** on the deal page (Overview), collapsed by default, remembered on this device. Its heading reads "Documents · 6 of 13 required". Open: Missing, Found, and Optional or not applicable, each row 44 px, with the type, the file name, the "as of" date you typed (never today), a status in words (Received, Read, Reviewed) and "n of m checks pass". Tap a rent roll, T-12 or OM row to open the panel that already reads it. A property type that is blank, not recognised, or names more than one kind ("Mixed use", "Multi-tenant office/retail") asks "What kind of property is this?" (Office, Retail, Net lease, Multifamily, Industrial); it is never turned into Retail. The list is advice and never stops a figure.
- **Add files** (several at once, or drop them on the card). A file is looked at on this device: the readers that already exist decide first (a rent roll PDF or an OM by `docKind`; a workbook or CSV by the T-12 month columns or the rent roll headings, and both matching asks). Only a reader (or your tap) sets a type. Anything else is scored on its first pages' text: a clear score says "looks like X: is that right?" and waits for your tap; a score under 2, or a lead of less than 2, asks "What is this?" with the best three types. A budget, an annual-only statement, a T-12 PDF or an appraisal is never typed by itself. The file name only puts its suggestion first; it never sets a type. A scanned PDF can be read by on-device OCR for its first page. The same file twice is "already added on …"; a file also in another deal is named on this device only.
- **Only a record is kept:** name, kind, size, SHA-256 fingerprint (null where the browser has no `crypto.subtle`), pages, the type and who set it (reader, text or you), status, and what a reader found. No document bytes, in storage or in a backup. At most 200 documents a deal.
- **Not applicable needs a reason**, typed in the row, with Undo. Remove from list, change type, mark reviewed and the as-of date each have Undo or are History entries.
- **The existing readers register their file** without any change to how they read: the OM reader, the rent roll PDF import and the T-12 import mark the file read, with its checks counted. The figures an OM read produced carry `sources[key].doc`, the record they came from.
- **Read with AI** appears on the card only when AI is on; on a confidential deal it is disabled and says why, and nothing is sent.
- **A merge restore takes the newer copy of a whole deal**, so documents added only on the older copy are lost (the same as the fee and credit records).
- **Data format:** schema 7, silent step `dd-init` (`deal.dd = { v: 1, preset, na, docs }`, set only when absent, so a newer list is never overwritten). Backups carry it; an older app says "made by a newer version" and restores nothing. `deal.dd` is listed in `NOT_CALCULATED` (no calculation reads it). The SHA-256 helper moved to `app/fingerprint.js` and Research uses it too.
- **Tested** with invented files: `tests/dd.test.js` (type table, checklist per kind of property, classifier table with ambiguous cases, property tests, fingerprint vectors, caps, no bytes), `tests/migrate.test.js` on an invented backup made by the real 4.7.73 code, `tests/e2e/dd-flow.mjs` (phone size; axe at phone and desktop; typing key by key; hostile file names as text; 200 documents under 150 ms). Chromium only; not tried on Safari or an iPhone.
- **Opening an older deal adds no History entry** (an empty list is not an edit), and reading an OM is one entry. A damaged backup's document list is cleaned on read (bad values null, 200 at most) so the deal screen always draws.
- **Saved results:** unchanged (618 saved deal results and 646 displayed figures identical).
