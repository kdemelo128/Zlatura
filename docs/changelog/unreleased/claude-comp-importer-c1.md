# Comps: add a spreadsheet or CSV of comps, mapped by you, with a check before anything is added

Comps could only come from CoStar PDFs or be typed. A firm's own list of comps, or a Zlatura CSV export, had no way in.

- **Add comps from a CSV or an Excel file.** Drop one on Comps, or choose it. The columns are matched by their headings (exact words, no guessing) and you can change any of them. The app's own comp layout (a Zlatura CSV export) is recognised and needs no mapping; "Comp template (CSV)" in the Comps menu gives you the headings to fill in.
- **It asks instead of guessing.** Percent or fraction (0.065), sale or asking prices, day-first or month-first dates, rentable or gross building area (a bare "GLA" is asked) and a land size with no unit each become a question. A cap column that mixes fractions and percents stops the import with the reason. Blank, "Undisclosed" and "n/a" stay blank, never zero. A price is never worked out from $/SF.
- **A preview before anything is added.** What will be added, what is already in the set (Skip is the default for the same sale; Add anyway is yours to choose), what was left out and why, and the checks. Import has an Undo.
- **Where each comp came from.** The Source row and the CSV's Source column say "Firm sheet (oct.csv, row 14)"; imported comps show an "imported" chip. A comp whose building area is gross or unknown is set aside until you include it.
- **The layout is remembered** and recognised next time ("Mapped as Firm sheet, used 2 times"), and is kept in backups. It is checked again against each new file.
- **Project files are now version 2.** Version 1 files open as before; a file from a newer version is refused with the existing words. Saved comps, backups and sessions from before open unchanged, with nothing rewritten on open.
- **Tested** with invented files only: `compimport.test.js`, `compmodel.test.js`, `comps-import-flow` (phone and desktop, axe, typing key by key), a 4.7.89 backup and a version 1 project that open unchanged; 14 mutation checks each fail a test. Saved results and the CoStar reader did not change (golden: 646 displayed figures, 0 changed; `analyze-golden` passes).
- **Known gap:** with 2,000 comps in the set an edit takes about 1.7 s on a desktop-size page (about 110 to 155 ms at phone size). The same slowness is on 4.7.89 with a large comp set, so it is not from the import; it is reported for a decision.
