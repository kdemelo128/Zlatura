# OCR on every PDF upload, tax bill, utility bill and unit mix readers, and three Model-step fixes

- **OCR wherever a PDF is uploaded:** the deal page's OM reader, the rent roll's Import from PDF, the T-12's PDF import and the Documents card now read a PDF with no text layer by the on-device OCR, with the same progress line and Cancel, the 12-page cap and the time budget, and unsure figures left blank and asked. An OM with text and some pages with none has just those pages read before the OM reader runs, so a scanned rent roll page is no longer missed (the OM reader's logic is unchanged; it is handed the text). A scan already read is not read twice. The toast, and the Documents card, say which pages were read by OCR and to check every figure. `omrr-flow` and `rrpdf-flow` changed: a scanned page is now read at the upload, not on a tap.
- **New small readers (`app/factsread.js`, `app/factsfile.js`):** property tax bill (tax year, parcel, assessed value, the year's tax, installments with due dates; installments are never added to the year's total), utility bill (utility type, service period, charge for the period, usage and unit; a two-month bill says it is two months), unit mix (type, count, SF, in-place and market rent). Only labelled figures are read, each with its page and line or sheet and row, shown in Start from documents and said on the Documents card. Month/day order, monthly or annual, in-place or market, SF per unit or total, which year, and an amount due that may carry an earlier balance are asked, with a button per answer, and the figures are worked out again. Nothing is stored on a deal: the deal has no field for any of these figures.
- **Zips:** a zip inside a zip inside a zip is opened (one line in `app/ddintake.js`, `ZIP_DEPTH` 2, for Codex's attention).
- **Model step:** the example's quick check uses a price that fits its NOI; Save as deal shows a plain message when it fails instead of staying silent; a calculator opened from the tool no longer overwrites the figures it remembers.
- **Tests:** `ocr-deal-pages`, `factsread` and `intake-facts` unit tests; browser flows `ocrdeal-flow` and `facts-flow`, with changed `omrr-flow`, `rrpdf-flow` and `uw-space-r3-flow`; each fails on the code before this change and each new guard was broken once.
